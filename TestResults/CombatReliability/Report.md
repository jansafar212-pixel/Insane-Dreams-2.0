# Sprint0035 — Weapon reloads, cover grenades, wallet reliability and combat fairness

Implemented in the existing Unity project on2026-10-28. Earlier sprint work and the release wallet hotfix were preserved. No staging, commits or pushes. This report covers the expanded gameplay-reliability brief in this folder's Brief.md, rather than the older Sprint0035 combat hotfix.

## Findings and changes

**LMG:** The actual native weapon was100rounds/8seconds with no magazine sprite or physical exchange configured. Its original37x14sprite already contained a6x6box container. The shared ammunition clock already transferred rounds atomically; no separate LMG arithmetic fault was reproduced. CombatReliabilitySetup extracts exactly those original container pixels into a native Point/32PPU sprite and removes them only from a new body variant. The complete original remains the inventory icon. The existing cached old/replacement-magazine rig now exchanges that container at its original socket. No alternate feed mechanism, loose physics debris, new rig or per-reload object creation. Capacity,8s base timing, recoil, damage, reserve limits and armor multiplier remain.

**Desert Eagle:** ArsenalSetup had copied the OfficerPistol's tiny2x4magazine and socket into the player weapon. The player now has a6x7slanted black magazine aligned inside the existing black grip, with no protruding extended magazine. Original pistol pixels, grip/muzzle pivot, seven rounds,2.8s reload and normal held-fire controls remain. Both turn directions and inserted/exchanging states were captured and inspected. The player pistol-debris component handles BackupPistol and LarperBuzzbox, not this weapon; the Eagle uses the existing bounded physical exchange rig.

**Sniper:** The inspected rifle has no modeled detachable magazine. Its five-round manual reload already uses the shared atomic clock; its release-to-fire aiming and one-second post-shot recovery are separate. No reproducible duplicate transfer or automatic recovery refilling ammunition was found. Existing aim cancellation remains, including reload while holding the aim stick. A real shared defect was that PlayerCombat.Reload checked CanOperate rather than CanUse, so it could begin during active tape healing. It now checks CanUse for all guns. Tests cover held-shot cancellation, manual completion, subsequent firing and unchanged recovery ammunition. No invented sniper magazine or changed control scheme.

**Cover grenades:** PlayerCover2D previously required a selected ammunition weapon. Selecting the throwable slot deliberately makes SelectedWeapon null, so it necessarily reset cover. The old throwable origin also cast horizontally from the crouched body, trapping the launch against the cover. Cover eligibility and downward-input ownership now accept the existing throwable slot. Aiming stays concealed. A successful release uses the existing damageable cover-height transition for a brief.24s exposure, then returns to concealment without moving the feet or granting immunity.

PlayerThrowables.TryReleaseOrigin is shared by preview and actual launch. It sweeps a small circle upward on the player's side, then outward above the cover. A blocked ceiling/path refuses the throw without spending stock. Ordinary throws also sweep toward a point beyond the player's body. The trajectory uses the same origin, aim, speed and gravity as launch, with a conservative.12radius against the actual.09projectile and the existing10Hz preview. It remains an approximation: existing projectile damping and later bounces are not a full physics simulation. Frag/flash/smoke effects, fuse, stock limits, pool size, cooldown and controls are unchanged. Existing projectile collision layers already exclude actors, including the player. Capture loss/explicit aim cancellation now cancels throwable aiming too.

**Wallets:** The actual prefab has a static trigger and no falling Rigidbody2D. EnemyWalletDrop spawned it at the death position minus.45with no solid/support checks; it could stay embedded or suspended indefinitely. The old pickup used player root position for both radius and LOS, despite the circle trigger overlapping the player's body; posture could therefore change collection behavior. Its visibility helper also treated smoke as a solid barrier. Finally, destroying a defeated actor destroyed its uncollected wallet.

WalletPickup now chooses nearby supported space with clearance for a crouched player. The bounded search samples at most19horizontal offsets within4.5units and casts at most32units down, rejects inside-solid ray starts, requires an upward surface and.65x1.05clearance, and prefers a nearby height rather than dropping a platform reward straight to a lower floor. It runs at initialization, with only two delayed support/clearance checks at approximately.6and2seconds; no ongoing world scans. Static placement avoids falling outside the level or ragdoll kicks. Collection measures the closest point of the real player collider, uses environmental LOS with smoke excluded, and keeps the1.95trigger radius. An uncollected reward belongs to the scene, surviving actor cleanup. Reward IDs, PlayerSupplies' claimed-ID set, notification, earnings event and mission settlement remain the existing once-only authority. No direct bank credit or duplicate payout path was added.

**Storage three-platform encounter:** The three02_Verticality actors and three new cloned cover objects were authored in Warehouse_Demo using Unity Editor APIs. Entry ground cover is atx16/floor0, middle retreat cover atx23.5/floor3.2, and upper approach cover atx28/floor6.4. They reuse the existing approved crate sprite, collider and components. Existing solid decks remain useful overhead barriers. Ladders, gaps, roster and world topology are unchanged. The three actors' detection ranges are18/16/14and visible-entry firing delays.30/.55/.85seconds. This staggers early acquisition without disabling AI, changing personalities or reducing damage. Existing viewport gate remains false for allowOffscreenFire. A controlled complete route using real movement/double-jump still reaches results; real cover/throw checks passed at all three heights. A subsequently reproduced opening-crossfire defect was also repaired locally: only the second warmup guard's detection range changes from22to10units, so it reacts as the player advances rather than joining the first encounter immediately. No global AI or weapon range/damage change.
